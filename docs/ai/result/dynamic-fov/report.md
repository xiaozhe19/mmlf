# 动态 FOV 与后台视锥（进行中）

## 问题

用户反馈飞行或疾跑时方块边缘不齐、有缝隙，快速旋转仍有裁剪。代码检查证实原主端 `getFov` Mixin 用设置中的固定 FOV 覆盖世界和手部 FOV，发布的姿态也只使用基础值；因此原实现无法同步 Minecraft 实际计算后的世界 FOV。Minecraft 1.21.1 的世界渲染还把受伤、行走晃动和屏幕效果乘入最终投影，但原后台剔除视锥单独生成透视矩阵，两者可能不一致。以上是确认的实现差异，尚不能断言其就是用户所见缝隙或裁剪的全部原因。

## 实现

主端不再覆写自身 FOV，在世界 `getFov(..., true)` 返回后发布真实 FOV；后台仅在世界投影应用 Overscan，手部 FOV 不再被覆写。曾尝试让后台 `prepareCullFrustum` 直接使用实际世界投影，但真实启动时 NeoForge 渲染线程在 `Frustum.offsetToFullyIncludeCameraCube` 持续占用 CPU、无法进入世界，因此已撤回该改动，继续使用 Minecraft 原有的剔除矩阵。视锥与受伤/行走晃动投影的一致性仍未解决。实际捕获仍记录渲染相机与 `RenderSystem` 投影。

## 验证

- `./gradlew.bat build --max-workers=1`：Fabric 和 NeoForge 编译以及现有测试通过，37 项任务中 6 项执行；不证明运行时 Mixin 注入或真实画面正确。
- 修复前会话中用户反馈疾跑/飞行时边缘不齐、有缝隙，快速旋转仍有裁剪。撤回问题视锥改动后，`./scripts/run-demo.ps1 -SelfTest -Foreground -LogLevel INFO` 新会话 `runtime/session-12100378000773406512` 的 Fabric 主端和 NeoForge 后台进入世界并持续合成；脚本相机控制、碰撞输出 passed=true，远端 use 有 success=true。真实启动和脚本覆盖不能证明疾跑/飞行画面问题已修复，正等待用户在新会话复测。
