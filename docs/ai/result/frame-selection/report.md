# 已完成帧选择（进行中）

## 问题与实现

后台 PBO 环形队列原来把所有已经完成的帧按旧到新依次发布，可能额外复制和通知已经过时的帧。现在每次 drain 检查所有完成的栅栏，仅发布最新且晚于上次发布的帧；其他完成帧释放，未完成的仍等待后续非阻塞检查。若旧帧在新帧之后才完成，也不会倒退发布。未改变 GPU 栅栏或帧文件完整性检查。

## 验证

`./gradlew.bat -PcoreOnly :common:test --tests dev.mmlf.common.CompletedFrameSelectorTest --max-workers=1`：通过，覆盖 GPU 完成顺序与帧号不一致、仅旧帧完成、无可用新帧等选择逻辑。随后 `./gradlew.bat build --max-workers=1` 通过，37 项任务中 19 项执行。最终代码真实会话 `runtime/session-1849693067686735165` 中双 Runtime 进入世界、持续合成并完成脚本相机/碰撞检查；未单独验证每种 GPU 栅栏乱序，也未比较端到端帧龄，因此尚不能声称时延或性能提升。

## 后续

在真实双 Runtime 和两个后台场景测量帧龄及跳过数，检查异常栅栏、帧丢弃、图像稳定性与会话切换；将结果与改动前可比条件的记录对照。
