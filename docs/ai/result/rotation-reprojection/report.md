# 纯旋转重投影优化（进行中）

## 问题与方案

用户反馈快速摇头仍有裁剪感，疾跑或飞行 FOV 变化时边缘仍不稳定。原 shader 总是对当前视线进行 40 步对数搜索；即使两个相机的有效投影中心相同、只有旋转或 FOV 差异，仍可能跨过薄表面并丢弃像素。实际丢失原因尚需进一步诊断，不能仅凭此推测认定根因。

当前 shader 对每条目标射线将近、远点投影到远端；仅当二者远端归一化坐标在 1e-6 内一致且都位于相机前方时，直接采样远端深度，按远端逆矩阵恢复表面并投影到主端，检查远端 UV、深度、齐次坐标和目标深度范围，再写入硬件深度。其他情况继续使用既有 Ray Marching 和深度一致性检查。此分支不能补回远端帧本身没有覆盖的画面，也不处理有视差时被遮挡的表面。

## 验证

- `./gradlew.bat build --max-workers=1`：37 项任务中 17 项执行，Fabric、NeoForge 编译和现有自动化测试通过。Java 构建不编译或执行 GLSL。
- 真实会话 `runtime/session-3160916805803249102` 中 GPU 程序初始化并持续合成，脚本相机控制和碰撞检查输出 passed=true。用户在近端方块遮挡远端时快速摇头，反馈仍有画面截切；该修改未达到视觉验收。

## 后续

核对运行时 shader 编译和真实画面，比较快速旋转与平移、不同 FOV、薄物体、深度遮挡及帧时间。若出现重影、错误遮挡、性能回退或 UV 覆盖不足，依据诊断数据继续修正，不移除深度约束。

用户截图 `fabric/screenshots/2026-10-28_20.22.27.png` 至 `2026-10-28_20.22.29_4.png` 记录了遮挡布置；同一会话快速运动时角度差与帧龄统计见 `docs/ai/result/adaptive-overscan/report.md`。尚不能仅凭截图判断每个截切像素是 UV 覆盖、深度验证还是剔除造成。
