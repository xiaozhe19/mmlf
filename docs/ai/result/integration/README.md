# Minecraft 1.21.1 双端 Demo 实机报告

日期：2026-10-28。Windows 11、Temurin JDK 21.0.3、RTX 3060 Laptop GPU。Fabric Loader 0.16.10 / Fabric API 0.115.4+1.21.1，NeoForge 21.1.172。

## 实际完成与结果

两个独立 JVM 分别运行原生 Bridge 和测试 Mod，自动生成隔离创造模式测试场景。Fabric 主窗口实际显示蓝色 Fabric 方块、橙色 NeoForge 方块，以及分别由各自 Runtime 加载的 Macaw's Doors / Macaw's Trapdoors 内容。

自动测试先连续改变主玩家视角，再发起与鼠标入口共用的 `requestInteraction` 请求。Coordinator 查询命中并定向路由。NeoForge 原生服务器执行后输出：

```
MMLF INTERACTION runtime=neoforge result=CONSUME state=Block{mmlf_neoforge_test:demo_block}[lit=true]
MMLF REVERSE EVENT state=Block{mmlf_fabric_test:demo_block}[lit=true]
MMLF INTERACTION runtime=neoforge result=CONSUME state=Block{mcwtrpdoors:oak_four_panel_trapdoor}[facing=north,half=bottom,open=true,powered=false,waterlogged=false]
```

上面省略了动作 UUID。Fabric 的反向事件证据同时保存在 `fabric-validation.log`。原生截图 `mmlf-core-demo.png` 展示两个 Runtime 的内容同时显示；`mmlf-thirdparty-demo.png` 展示 NeoForge 活板门打开后的画面。没有向 Fabric 复制远端纹理、注册远端方块或重写远端渲染。

## 发现的问题与修复

1. 依赖和开发类路径问题：对齐游戏 Gson / SLF4J，Fabric 开发运行使用测试 Mod 源码输出，NeoForge 为 WebSocket 配置 additionalRuntimeClasspath。
2. 初始采集发生在世界深度清除后：钩子前移到清深度之前。
3. 旋转时远端层消失：主窗口渲染使用远端完成帧对应的相机，输入目标姿态独立发送，增加显示延迟以保证同一投影配对。
4. Fabric 在 NVIDIA glTexSubImage2D 中原生崩溃：显式保存、清零并恢复像素传输行跨度、跳过偏移和 PBO 绑定。修复后数分钟验证期间未新增崩溃；不是长时间稳定性保证。
5. NeoForge GLFW 限帧等待中崩溃：隔离原生库目录，并为开发会话提供 Java 等待替代路径；根因尚未证实。
6. Coordinator 退出死锁：回调改用独立状态锁。

## 验证边界

已验证原生启动、真实颜色/深度帧传输、同窗画面和自动触发的跨端原生交互、反向事件、第三方活板门打开。物理鼠标入口尚未独立确认，自动步骤调用了同一请求函数。第三方门已原生显示，开关尚未单独验收。

仍有限制：动态显示有延迟；透明材质和复杂渲染器不保证；重复原版渲染过滤正在适配 NeoForge 扩展阶段；完整远端碰撞、跨端物品栏、合成、生存和任意 Mod 兼容不在本 Demo 范围。CPU、堆内存、渲染钩子频率与 RTT 已输出，RSS、校准后的端到端帧延迟、相机误差及完整吞吐统计尚不完整。近期日志中稳定 RTT 通常低于 2ms，主端渲染钩子频率约 80–110/s，不等同于通用性能承诺。

## 运行

仓库根目录执行 `scripts/run-demo.ps1 -SelfTest`；可选第三方 Mod 用 `scripts/fetch-demo-mods.ps1` 从固定 Modrinth 版本下载并校验 SHA-512。启动入口创建独立游戏目录、协调器和双端开发运行。首次运行需联网下载合法的官方开发依赖。普通用户单 Bootstrap JAR 安装尚未实现。

后续修复：读取帧槽位忙或已覆盖时，不再丢弃远端图层；相机和合成共同使用上一张完整帧。代码已编译，视觉闪烁改善交由用户手动复验。统一启动器的 Fabric runDir 已修正为相对路径，正在用统一入口运行手动场景。

统一入口实测修正：Fabric Loom 的 runDir 需使用相对项目路径，绝对 Windows 路径会被错误拼接；NeoForge Mixin 必须在专属子包，不能覆盖 Mod 入口所在包。这两项已修正。当前启动为手动场景，不存在 self-test 标记，不会自动转向或发起交互。

## 用户手动测试后的下一版修正（尚未实机复验）

用户确认完整帧保留后不再闪烁，并报告卡顿、无挥手/声音、蓝色不触发橙色、飞行投影偏移、左键穿透和无法放置。

本次修正增加统一 use/attack 请求及原版手持物/潜行信息；服务端原生破坏和放置，远端放置的原版方块纳入归属与渲染。对象尚未完成索引时先阻挡射线，避免操作后方。交互确认后主端挥手，捕获该次服务器操作的原生声音事件并在主端播放（仅能播放主端拥有的声音资源）。两个测试 Mod 的事件现在双向连接，接收端直接改状态而不再次发送，避免循环。

飞行时固定到帧记录的 FOV，减少主端飞行 FOV 与后台物理状态的差异；帧读取改为双缓冲复用以减少堆外分配。这些变化的编译和自动化结果不代表手动验证通过。当前已打开的游戏仍运行上一版，未重启；本次未使用 Computer Use。

放置当前限于创造模式基础场景，不提供跨端自定义物品组件或生存物品消耗同步。声音按事件 ID 路由，不是跨进程音频混流；主端缺失的远端自定义声音资源尚不支持。

用户后续报告：远端无碰撞、右键有声但画面无变化、偶发无效。日志确认多次快速开关。新增原版四 tick 右键冷却，状态扫描改为两 tick；导出原生 VoxelShape AABB 并在主端玩家的客户端及集成服务器碰撞中加入这些形状。碰撞实现不涵盖完整跨端物理/实体交互，仍待运行验证。

自动碰撞用例未通过：运行中日志显示远端橙色测试方块在用例执行前被 attack 请求销毁，固定坐标查询得到零形状。本次不能据此宣称碰撞已通过。另将 Demo 的右键改为每次按下只发一次，松开后才能再次触发，避免持续按住时开关反复切回。
