# Demo 1 收尾报告

日期：2026-10-28。Windows 11、RTX 3060 Laptop GPU（6 GB）、Temurin JDK 21；Minecraft 1.21.1，Fabric Loader 0.16.10 / Fabric API 0.115.4+1.21.1，NeoForge 21.1.172。第三方测试 Mod：Macaw's Doors 1.1.5（Fabric）、Macaw's Trapdoors 1.1.5（NeoForge）。

## 结论

`docs/manual/initial_demo.md` 第 11 节的测试 A–E，以及补充要求里"当前 Demo 的最低要求"，**均已在真实 Minecraft 中验证**。验证方式包括：

- 两个方向的手动验收（用户执行）；
- 多轮自动自测；
- 日志和截图证据。

另外，主端不再固定为 Fabric：两个加载器都能当主窗口，两个方向都通过了验收。

快速转头时屏幕边缘的远端物体会被裁切，这一项标记为**未完成**（见"尚未完成"）。

## 1. 已经实际完成的功能

- **双端原生运行**：Fabric 与 NeoForge 在两个独立 JVM 里加载各自的 Bridge、测试 Mod 和第三方 Mod，彼此不依赖对方的加载器 API。
- **通信**：Loopback WebSocket Coordinator，带令牌握手、心跳、断线检测，按对象归属路由消息，支持双向自定义事件。
- **对等主端**：主窗口由会话决定，不由加载器决定。直接启动任意一端的客户端，它就会托管会话、成为主窗口并在后台拉起另一端；也可以用 `run-demo.ps1 -Primary fabric|neoforge`。
- **画面融合**：
  - 后台用 PBO 异步读回颜色和深度，通过 seqlock 共享帧文件发布；
  - 主端用 GPU 全屏着色器合成，由硬件深度测试决定遮挡；
  - 相机姿态不一致时，沿视线步进重投影，遇到被揭开的遮挡区域就丢弃该像素；
  - 后台在区块构建阶段过滤不属于自己的方块，不画云和方块选择框，视野放宽到 1.25 倍并预测相机姿态；
  - 远端帧超过 1 秒未更新时隐藏远端层。
- **交互**：Coordinator 做射线仲裁，交给方块所属的那一端原生执行，包括右键、左键破坏、中键选取，以及放置远端物品；有挥手动作、原生声音和破坏粒子，并支持反向事件。
- **碰撞**：主端玩家与远端方块碰撞（导出原生碰撞形状）。
- **物品外观**：远端手持物和快捷栏图标使用所属端原生渲染的像素；原生图标到达之前格子显示为空，不再闪纸张代理。
- **会话管理**：
  - 主端等后台世界就绪后才进入世界（等待界面上有"直接进入"按钮）；
  - 后台窗口从创建起就隐藏，NeoForge 当后台时关闭它的早期加载窗口；
  - 主窗口关闭或进程被强制结束后，后台约 3 秒内退出（看门狗、`session_end` 广播、5 秒断线兜底）。
- **统一 Mod 目录**：`mmlf/mods/` 按标准元数据分拣到对应加载器；遇到有歧义或无法识别的 JAR 会给出提示，不会自动归类。
- **性能记录**：两个 JVM 的 CPU、堆内存和 RSS，帧率，读回耗时，远端帧龄，消息往返时间，相机误差，Coordinator 吞吐量。

`./gradlew.bat build` 全部模块编译成功，自动化测试全部通过。测试包括：

## 3. 已在真实 Minecraft 中验证

**用户手动验收**（清单见 `acceptance-checklist.md`），两个方向 10 项全部通过：

- NeoForge 当主：`run-demo.ps1 -Primary neoforge`，session-6618770401758477809；
- Fabric 当主：`run-demo.ps1 -Primary fabric`，session-10425239704648128145。

本轮之后修改了窗口隐藏和关闭广播，又用 Fabric 当主拉起一次（session-13252127803828223830）：

- 整个启动过程中屏幕上只出现 Fabric 主窗口；
- 后台 NeoForge 读取了 `earlyWindowControl = false`；
- 关闭时 `session_end_sent` 只发了一次，NeoForge 记录 `background_stopping`。

**自动自测**（客户端托管，两个方向）：相机控制、碰撞（Fabric 当主 `dx=0.2`，NeoForge 当主 `dx=-0.2`）、跨端交互、反向事件、第三方门和活板门、选取、放置、粒子。

**实测指标**：

| 场景 | 后台读回中位数 | 远端帧龄中位数 |
|---|---|---|
| 主窗口负载较轻 | 约 13 ms | 15–18 ms |
| 用户正常游玩（2560×1351，后台约 62 FPS） | — | 约 37 ms |

## 4. 尚未完成

- **快速转头裁切（未完成）**：超快速甩头时，屏幕边缘的远端物体被裁切，之后能看到重新出现的过程。原因是两个客户端同时以高分辨率渲染，GPU 饱和，后台帧率上不去，远端帧落后约 37 ms。可选方向：降低后台分辨率、快速转头时临时同步、逐帧同步（会增加输入延迟）。
- 远端物品选取和放置在 NeoForge 当主时，只由用户手动验证；自动自测因场景不对称没有覆盖到。
- 透明材质（水、玻璃）按不透明合成，主端的半透明表面会挡住后面的远端物体。
- 原生按键转发（由所属端的客户端自己执行点击）、手部和 HUD 分层、合成调试视图都还没做。
- 启动依赖开发环境（各 Bridge 的 Gradle `runClient`）。可安装的单个 Bootstrap JAR、普通启动器实例之间互相拉起，都还没实现。
- 跨端物品栏和物品组件、生存模式、实体和完整物理同步、Forge 第三端，都不在本 Demo 范围内。

## 5. 当前最大的技术障碍

两个完整 Minecraft 客户端争用同一块 GPU，再加上跨进程的帧延迟。画面正确性已经解决；剩下的问题都是延迟和资源问题：快速转头裁切、笔记本上后台帧率不足。另一个障碍是脱离开发环境的启动：怎样在玩家自己的启动器里拉起另一种加载器的实例。

## 6. 下一步最值得做的

1. 降低后台渲染分辨率，或做按需同步，缓解快速转头裁切；
2. 单 Bootstrap JAR 加 Runtime Manager，让用户能像安装普通 Mod 一样使用；
3. 原生按键转发和 HUD 分层，让远端 Mod 的自定义交互（长按、使用物品、GUI）原生生效。

## 本轮关键问题与修复记录

- Fabric 当后台时，原版地面没有被过滤，导致摩尔纹。改为 `SectionCompilerMixin` 过滤（Indigo 会绕过 `renderBatched`）；第一版在 NeoForge 上没有注入成功，改成 `compile*` 后两端都注入成功。
- 后台的云和方块选择框被合成进主窗口，导致云抽搐、出现杂线框。后台改为关闭云、不画选择框。
- 自测脚本按 Fabric 当主写死了坐标，改为根据远端方块所在的一侧镜像。
- 启动时先看到 NeoForge 的窗口。改为窗口创建即隐藏，并关闭 NeoForge 当后台时的早期加载窗口。
- 关闭时 `Minecraft.stop()` 每帧都被调用，导致 `session_end` 广播了几十次，改为只发一次。
- 一次崩溃打断了后台 Gradle 构建，留下了 Loom 缓存锁；之后 VS Code Java 扩展的 Gradle 守护进程占用了 `mappings.jar`，导致构建失败。用户关闭 VS Code 后恢复。
