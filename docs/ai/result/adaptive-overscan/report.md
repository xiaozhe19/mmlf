# 视野覆盖与采样密度（实验中）

## 用户现象和证据

用户在 `runtime/session-3160916805803249102` 反馈：近端方块遮挡远端内容时，快速摇头仍有画面截切感；后台画面锯齿明显。截图 `fabric/screenshots/2026-10-28_20.22.28.png` 到 `20.22.29_4.png` 显示了该遮挡布置，静态截图不能确定每一个运动瞬间的失败原因。

同一会话 20:22:24 和 20:22:35 的 `metrics/remote_frame` 分别记录角度差 P95 30.15°、31.55°，帧龄 P95 40.53 ms、45.30 ms；角度是 yaw/pitch 差的欧氏近似，不能表示具体某个截图像素的失败原因。对于垂直 FOV 70°、16:9 画面，固定 tangent scale 1.25 的水平、垂直额外覆盖均约 6°，远小于上述角差。覆盖不足是有数据支持的候选原因，但深度检查、剔除及时间采样也需独立诊断。

本次启动时后台帧与主端均为 1280×720，后台没有被固定降到更小的缓冲区。1.25 倍视野压到同样像素数意味着中心附近每个方向约 80% 的采样密度，面积约 64%；GPU 合成纹理使用最近邻采样。这可以解释清晰度损失和锯齿，但仍需真实对照评估。

## 实验实现

新增可选 `-Dmmlf.adaptiveOverscan=true`：静止时 tangent scale 1.0，根据角速度、预测时间及水平/垂直投影几何增加视野，受 `mmlf.overscan` 上限（默认 1.25）约束；快速扩大、以滞回和平滑速度缩小。尚未按 GPU 负载自适应，也无法保证角差超出上限时有足够覆盖。实验默认关闭，以免在未验证时降低快速转头的视野余量。

## 验证与限制

首次 `./gradlew.bat build --max-workers=1` 中 `AdaptiveOverscanTest` 的水平与垂直敏感度大小假设错误，测试失败；修正为独立数值期望后重跑 `./gradlew.bat build --max-workers=1` 通过，37 项任务中 17 项执行。尚未完成真实游戏的质量、性能、快速反向及固定 1.00/1.25/1.50/1.75 对照。不能把实验描述为已解决裁剪或锯齿。

## 真实实验

通过 `JAVA_TOOL_OPTIONS=-Dmmlf.adaptiveOverscan=true` 启动 `./scripts/run-demo.ps1 -SelfTest -Foreground -LogLevel INFO`，会话 `runtime/session-15288233484514026951` 成功启动、合成并完成脚本相机及碰撞检查。一个接近静止的 1224 样本窗口 overscan P50/P95/P99 为 1.0161；之后运动窗口 P95 达到 1.25 上限，主端对应窗口角度差 P95 21.89°、帧龄 P95 40.36 ms。静止时未回到 1.0 是滞回逻辑的缺陷，已修改允许静止继续回落；新增静止回落单元测试并通过完整构建，修改尚未在真实游戏验证。该实验表明动态参数确实变化，不证明快速摇头截切已经解决。

## 用户补充：窗口大小影响

用户反馈默认窗口下裁剪和变形不明显，全屏时明显。会话 `runtime/session-3160916805803249102` 日志中后台目标从 1280×720 调整为 2560×1351，像素数由 92.16 万增至约 345.86 万（约 3.75 倍）。同一会话的不同统计窗口，调整前远端帧龄 P50 约 15–17 ms，之后示例约 30–40 ms；后台捕获耗时的部分样本也从约 8 ms 增至约 18–22 ms。时间窗口内玩家操作和系统负载并未严格控制，这些数据支持高分辨率带来更高负载和帧龄的排查方向，不证明它是唯一根因，也不等同严格对照实验。
